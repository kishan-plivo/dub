# Local Development Database Setup

This document outlines the steps and considerations for configuring the application to use local PostgreSQL and Redis instances instead of the default PlanetScale (MySQL) and Upstash Redis services.

## Local PostgreSQL Setup (Experimental)

Switching from the default PlanetScale MySQL database to a local PostgreSQL instance is possible but involves several steps and requires careful migration, especially concerning database-specific features.

**Prerequisites:**

*   A local PostgreSQL server installed and running.
*   A PostgreSQL database created for this application.

**Steps:**

1.  **Update Prisma Schema Provider:**
    *   Open the main Prisma schema file: `packages/prisma/schema/schema.prisma`
    *   Locate the `datasource db` block.
    *   Change the `provider` from `"mysql"` to `"postgresql"`.

    ```prisma
    // packages/prisma/schema/schema.prisma
    datasource db {
      // provider     = "mysql"
      provider     = "postgresql" // Change this line
      url          = env("DATABASE_URL")
      relationMode = "prisma"
    }
    ```

2.  **Update Database Connection URL:**
    *   Modify the `DATABASE_URL` variable in your `.env` file to point to your local PostgreSQL instance.
    *   Example PostgreSQL URL format: `postgresql://USER:PASSWORD@HOST:PORT/DATABASE?schema=public`

    ```dotenv
    # .env
    # Replace the existing DATABASE_URL
    DATABASE_URL="postgresql://postgres:password@localhost:5432/dub?schema=public"
    ```

3.  **Review Schema for MySQL-Specific Types:**
    *   Carefully examine all models across all `.prisma` files in `packages/prisma/schema/`.
    *   Look for MySQL-specific type attributes like `@db.Text`, `@db.LongText`, `@db.TinyInt`, `@db.UnsignedInt`, etc.
    *   Replace these with their standard Prisma equivalents or PostgreSQL-specific types (`@db.Text` is often okay, but others might need changing).
    *   Refer to the [Prisma PostgreSQL documentation](https://www.prisma.io/docs/reference/database-reference/database-features/postgresql) for type mappings.

4.  **Address Full-Text Search:**
    *   The current schema uses the `fullTextSearch` and `fullTextIndex` preview features, which are specific to MySQL/MariaDB in Prisma.
    *   **Remove Full-Text Features from Schema:**
        *   Delete any `@@fulltext(...)` index definitions from your models.
        *   In `packages/prisma/schema/schema.prisma`, remove `"fullTextSearch"` and `"fullTextIndex"` from the `previewFeatures` array in the `generator client` block.
    *   **Re-implement Search Logic:** Any application code that relies on Prisma's `fullTextSearch` will need to be rewritten using PostgreSQL's full-text search capabilities (e.g., `to_tsvector`, `to_tsquery`). This might involve using Prisma's `$queryRaw` or adapting data fetching logic significantly.

5.  **Generate and Apply Migration:**
    *   Run Prisma Migrate to create a new migration based on the schema changes and apply it to your local PostgreSQL database.
    *   From the workspace root, run:
        ```bash
        pnpm dlx prisma migrate dev --name switch-to-postgres
        ```
    *   Carefully review the SQL generated by Prisma before confirming.

6.  **Review Raw SQL Queries:**
    *   Search the codebase (especially within `lib/` or `api/` directories) for any raw SQL queries using `prisma.$queryRaw` or `prisma.$executeRaw`.
    *   Ensure these queries use standard SQL or PostgreSQL-specific syntax, not MySQL syntax.

**Considerations:**

*   This migration is complex due to differences in type systems and features like full-text search between MySQL and PostgreSQL.
*   Thorough testing is required after the switch.

## Local Redis Setup

Switching from Upstash Redis (cloud-based, REST API) to a standard local Redis instance is more straightforward.

**Prerequisites:**

*   A local Redis server installed and running on the default port (`6379`) without a password.

**Steps:**

1.  **Install `ioredis` Client:**
    *   Navigate to the web application directory and add the `ioredis` library:
        ```bash
        cd apps/web
        pnpm add ioredis
        cd ..
        ```

2.  **Modify Redis Client Configuration:**
    *   Open the Redis configuration file: `apps/web/lib/upstash/redis.ts`
    *   Replace the contents with the following to use `ioredis` and connect to the default local instance:

    ```typescript
    // apps/web/lib/upstash/redis.ts
    import Redis from 'ioredis';

    // Initiate Redis instance by connecting to localhost:6379
    export const redis = new Redis();

    // Optionally, configure host/port/password via environment variables:
    // export const redis = new Redis({
    //   host: process.env.REDIS_HOST || '127.0.0.1',
    //   port: process.env.REDIS_PORT ? parseInt(process.env.REDIS_PORT, 10) : 6379,
    //   // password: process.env.REDIS_PASSWORD,
    // });
    ```

3.  **Remove/Ignore Upstash Environment Variables:**
    *   You no longer need `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` in your `.env` file for the application to connect to Redis (though other parts of the system might still use them if not fully migrated).

**Considerations:**

*   Ensure your local Redis server is running before starting the application.
*   If your local Redis uses a different port or requires a password, uncomment and adjust the configuration block in `apps/web/lib/upstash/redis.ts` and set the corresponding environment variables (`REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD`).
